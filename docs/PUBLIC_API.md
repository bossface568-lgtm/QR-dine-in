# QR Dine SaaS — Public Customer API Specification

## Overview

The **Public Customer API Layer** provides secure, high-performance, and sanitized data access exclusively for the QR Dine Customer Application (`apps/customer`).

### Security Principles
1. **Zero Database Exposure**: Customer clients consume sanitized Data Transfer Objects (DTOs), never raw database rows.
2. **Data Isolation**: Sensitive fields (`auth_user_id`, `created_by`, `updated_by`, `deleted_at`, owner credentials, GST/PAN numbers, internal notes, RLS policies) are automatically stripped before sending responses to the client.
3. **Multi-Stage Validation**: Every table token request is validated against restaurant status, branch status, table active status, and tenant ownership.

---

## Service Methods & Endpoints

All public methods are accessible via `publicCustomerService` in `@qrdine/lib` and standard REST endpoints under `/api/public/`.

---

### 1. GET Public Restaurant Information

`GET /api/public/restaurants/{restaurantSlug}`

### 5. GET Table Information & Token Resolution

`GET /api/public/table/{tableToken}?slug={restaurantSlug}`

Validates table QR scan token and resolves table, branch, and restaurant information.

#### Error Responses
- `404 Not Found`: `TABLE_NOT_FOUND` — Invalid or deleted table QR code.
- `400 Bad Request`: `EXPIRED_TABLE_TOKEN` — Table QR has been regenerated by admin.
- `403 Forbidden`: `TABLE_INACTIVE` — Table is currently out of service.
- `403 Forbidden`: `RESTAURANT_UNAVAILABLE` — Restaurant is temporarily inactive.

#### Success Response (`200 OK`)
```json
{
  "valid": true,
  "restaurant": {
    "id": "2c5b3a8e-89fe-419f-b796-1d022c5fbaeb",
    "name": "The Golden Fork",
    "slug": "golden-fork",
    "status": "active"
  },
  "branch": {
    "id": "b_01",
    "name": "Jubilee Hills Main",
    "code": "JH-01",
    "address": "123 Gourmet Street",
    "phone": "+91 9876543210",
    "is_active": true
  },
  "table": {
    "id": "t_01",
    "table_number": "T-12",
    "table_token": "T-MAIN-012",
    "capacity": 4,
    "section": "Terrace Garden",
    "floor": "First Floor",
```

### 6. GET Optimized Batch Menu Payload

`GET /api/public/restaurants/{restaurantSlug}/full-menu?tableToken={tableToken}`

Combines Restaurant, Branding, Branch, Table, Categories, and Menu Items into a **single, highly optimized database payload** for instant customer app rendering.

---

## Future Extensibility Roadmap

The DTO models support seamless integration of upcoming modules without breaking client contracts:
- `variants`: Array of `PublicProductVariant` (size, portion, preparation options)
- `modifier_groups`: Array of `PublicModifierGroup` (toppings, add-ons, extra cheese)
- `table_session`: Real-time session token management for order tracking and waiter calls
